# TASK-002-HUMAN-002-FIX-LITE｜最小化修复结果发布完整性

## 目标

修复人工结果分析工具的发布顺序：完成版JSON或`review-manifest.json`在分析开始后发生变化时，不得留下本次生成的正式结果。

## 实现范围

- 分析开始时将完成版JSON和manifest各读取一次到固定内存快照；
- 从内存快照执行严格JSON解析、manifest绑定校验、统计和模型决策；
- 五类本地/公开结果先生成到同一个临时输出目录；
- 正式替换前重新计算两个原始输入文件的SHA-256；
- 两个哈希均与开始时一致后，才用临时文件替换正式结果；
- 输入变化或结果生成失败时自动清理临时目录，不修改既有正式结果；
- 增加正常发布、双输入变化、生成失败清理和统计/决策不变的定向测试。

## 明确边界

- 不建立通用事务框架、复杂备份或多层回滚系统；
- 不大规模拆分或重构`result_analysis.py`；
- 不改变现有校验规则、统计公式、模型分数、排序或决策；
- 不修改既有审核报告`tasks/reports/TASK-002-HUMAN-002-R_AUDIT.md`；
- 不上传原始JSON、用户文本、媒体或`local-data/`；
- 不创建新分支或新PR，继续使用现有分支和Draft PR #4；
- 不标记Ready，不启用auto-merge，不合并PR；
- 不执行TASK-003。

## 完成条件

- 正常分析可发布全部正式结果；
- JSON在发布前变化时分析失败，原正式结果逐字节不变；
- manifest在发布前变化时分析失败，原正式结果逐字节不变；
- 生成失败及输入变化后无FIX-LITE临时目录残留；
- 正常模型统计和生产决策与修复前一致；
- 新增定向测试及完整source-only测试均为0 failed；
- 生成FIX-LITE结果报告，提交到现有Draft PR #4并运行`Get-PRHandoff.ps1`。
